# Exact-run AWS application task boundary

Status: code and synthetic tests only. No candidate browser task is deployed or enabled in staging or production.

The hosted launcher passes one candidate ID, run ID, and signed capability to a short-lived Fargate task. The trusted run-state broker reads `CANDIDATE#<candidateId>/DISPATCH#<runId>` consistently and verifies the row's envelope against the signed capability. The task has no direct DynamoDB access and never calls SQS `ReceiveMessage` or `DeleteMessage`. An older message for another candidate cannot be received or redriven by this task. The durable dispatch row is the hosted queue.

`createAwsQueuedRunRuntime` connects that exact row to brokered entitlement and consent checks, the durable submission journal, and candidate artifacts. The task must acquire a journal lease before asking the artifact broker for short-lived credentials. Its role may invoke only the named broker; it has no direct DynamoDB, SQS, S3, KMS, or STS grant. The trusted run row supplies billing subject, job, and profile artifact ID; no candidate profile data is in the dispatch envelope. The synthetic adapter opens a private Chromium profile on an intercepted `.invalid` host, fills reviewed answers, and requires a confirmation with the exact requisition ID. Real-site submission is disabled.

A confirmed journal state is written before the dispatch row is marked completed. If a task crashes before completion, the scheduled controller observes ECS `STOPPED` while retaining its sole launch slot. It reads the journal: confirmed repairs the dispatch row without another click; `not_started` can requeue with a fresh ECS client token for at most two retries, with the retry index and slot release committed in one Dynamo transaction; an uncertain or exhausted run requires reconciliation. A transient reconciliation failure keeps the slot so the next sweep can retry. Consent and payment are rechecked before each relaunch and before the final submit intent.

The legacy standalone `SqsApplicationQueueReceiver` remains for non-hosted queue tests. It is not wired into the staged hosted browser task. Its in-memory tests do not establish deployed Fargate behavior. The run-state broker is implemented in draft PR #261 but not deployed. The remaining gates are a disposable AWS staging run with two candidates and crash injection, and an independent human security review. Keep the synthetic task flag and real-site submission flag off until those gates pass.
