# Exact-run AWS application task boundary

Status: code and synthetic tests only. No candidate browser task is deployed or enabled in staging or production.

The hosted launcher passes one candidate ID, run ID, and signed capability to a short-lived Fargate task. The task reads `CANDIDATE#<candidateId>/DISPATCH#<runId>` with a strongly consistent DynamoDB read and verifies the row's envelope matches both IDs. It never calls SQS `ReceiveMessage` or `DeleteMessage`. An older message for another candidate cannot be received or redriven by this task; the browser task role has no SQS receive/delete grant. The durable dispatch row is the hosted queue.

`createAwsQueuedRunRuntime` connects that exact row to current entitlement and consent reads, the durable submission journal, and brokered candidate artifacts. The task must acquire a journal lease before asking the artifact broker for short-lived credentials. The task role has no direct S3/KMS permission. The trusted run row supplies billing subject, job, and profile artifact ID; no candidate profile data is in the dispatch envelope. The synthetic adapter opens a private Chromium profile on an intercepted `.invalid` host, fills reviewed answers, and requires a confirmation with the exact requisition ID. Real-site submission is disabled.

A confirmed journal state is written before the dispatch row is marked completed. If a task crashes before completion, the scheduled controller observes ECS `STOPPED` while retaining its sole launch slot. It reads the journal: confirmed repairs the dispatch row without another click; `not_started` can requeue with a fresh ECS client token for at most two retries, with the retry index and slot release committed in one Dynamo transaction; an uncertain or exhausted run requires reconciliation. A transient reconciliation failure keeps the slot so the next sweep can retry. Consent and payment are rechecked before each relaunch and before the final submit intent.

The legacy standalone `SqsApplicationQueueReceiver` remains for non-hosted queue tests. It is not wired into the staged hosted browser task. Its in-memory tests do not establish deployed Fargate behavior. The remaining gates are the tenant-scoped run-state broker, a disposable AWS staging run with two candidates and crash injection, and an independent security review. Keep the synthetic task flag and real-site submission flag off until those gates pass.
