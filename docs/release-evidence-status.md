# Public release evidence status (2026-11-26)

This is a dated inventory of evidence on `main`, open draft work, and the
remaining decisions for an **unattended public release**. It does not grant
permission to enable a provider or to run a real employer application. The
exit criteria remain in [autonomy release requirements](autonomy-release-requirements.md)
and the [monitored beta protocol](monitored-beta-protocol.md).

| Gate | Evidence on `main` | Still required before public use |
| --- | --- | --- |
| Discovery and ranking | Scheduled discovery, official-source checks, deduplication, and freshness backfill exist. | Measure source coverage and cadence in beta. [#75](https://github.com/joshuaraja1/openapply-agent/issues/75) remains open; [#158](https://github.com/joshuaraja1/openapply-agent/pull/158) and stacked [#192](https://github.com/joshuaraja1/openapply-agent/pull/192) are draft signed-in board work. Do not claim coverage of every job site. |
| Provider forms | Controlled Chromium suites complete 100 **synthetic** applications each for Greenhouse and Ashby; other provider fixtures and guarded handoffs exist. See the [completion gate](provider-completion-gate.md) and [staging matrix](provider-staging-matrix.md). | A default-off provider allowlist is in `main`; enable each provider only after consented, low-volume real-site testing for the exact requisition, upload, conditional questions, interruptions, and employer confirmation. The per-provider procedure is [draft #171](https://github.com/joshuaraja1/openapply-agent/pull/171). Synthetic receipts are not employer receipts. |
| Browser recovery | The owned-browser queue, job-bound checkpoints, and `submission-uncertain` handoff exist. | Prove crash recovery at the final click without a second click, including keeping the exact browser tab and receipt. [#153](https://github.com/joshuaraja1/openapply-agent/issues/153) is open. Owner-service [#163](https://github.com/joshuaraja1/openapply-agent/pull/163), [#182](https://github.com/joshuaraja1/openapply-agent/pull/182), [#186](https://github.com/joshuaraja1/openapply-agent/pull/186), and [#190](https://github.com/joshuaraja1/openapply-agent/pull/190) are inactive draft slices, not the production queue path. |
| Candidate setup and privacy | A private first-run editor, handoff screen, state-only export/deletion controls, encrypted SQLite state, and a scoped email alert staging test are present. | Exercise one complete setup → discovery → application → handoff → resume → confirmed outcome path on every supported OS. Complete full-product export/deletion for browser profiles, source files, PDFs, secrets, backups, and connected-account grants beyond the current [state-only control](data-controls.md). [#58](https://github.com/joshuaraja1/openapply-agent/issues/58) is open. |
| Mailbox consent | Optional self-hosted Gmail/Microsoft OAuth flows exist. | Product-owned client registration, approved redirect URIs and scopes, consent verification, and revoked-token recovery remain [#71](https://github.com/joshuaraja1/openapply-agent/issues/71). [Draft #193](https://github.com/joshuaraja1/openapply-agent/pull/193) checks self-hosted setup; it does not register product clients. A verified Resend **sending** domain and delivered operator/staging alerts do not prove mailbox **reading** OAuth or queue-triggered delivery to beta users. |
| Distribution | Portable CLI smoke runs on macOS, Windows, and Linux; unsigned macOS PKG and Windows NSIS staging packages have disposable install/rollback drills. | Publish signed and verified artifacts for all three OSes and test actual clean install, update, failure rollback, uninstall, browser setup, and private-state preservation on clean machines. The macOS PKG needs a Developer ID Installer identity and notarization profile; Windows needs a signing certificate/service. Linux has [draft #170](https://github.com/joshuaraja1/openapply-agent/pull/170). These packages are CLI staging builds, not a complete consumer app. See [distribution](distribution.md) and [Windows NSIS](windows-nsis.md). |
| Speed and reliability | Controlled tests and a planned measurement protocol exist. | Report 30 warm-run samples per stage on each OS, median/p95, OS-kill recovery, 1,000 duplicate-submit attempts, and denominators for confirmed outcomes. [Draft #181](https://github.com/joshuaraja1/openapply-agent/pull/181) is synthetic and cannot establish real-site latency or crash-free beta rate. [#74](https://github.com/joshuaraja1/openapply-agent/issues/74) remains open. |
| Consented beta | A [two-week protocol](monitored-beta-protocol.md) and consent template exist; [draft #189](https://github.com/joshuaraja1/openapply-agent/pull/189) adds a private evidence ledger. | Obtain explicit candidate consent and named operator coverage, pass entry checks, then run 14 consecutive monitored days with real candidate applications in approved scope. Record exact-job confirmations, failures, handoffs, source coverage, latency, and support outcomes. [#60](https://github.com/joshuaraja1/openapply-agent/issues/60) remains open. |
| Independent review | CI, CodeQL, and AI-assisted bug/security reviews have caught defects. | Commission an independent human security assessment of browser sessions, local secrets, email, candidate data, submission, installer/update, and deletion; fix findings and rerun affected gates. CI and agent reviews do not satisfy this requirement. |

The release owner should record a dated go/no-go decision with the supported
OS/provider matrix, exact build and CI links, real-site and beta evidence,
privacy/site-terms review, signing and OAuth status, external security findings,
open defects, and rollback owner. Keep public unattended application disabled
until all gates pass or narrow the advertised scope and repeat the decision for
that scope. Student subscriptions in [#120](https://github.com/joshuaraja1/openapply-agent/issues/120)
are a later product decision, not evidence for this release.
